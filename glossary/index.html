Glossary

Terms used across the site, in plain language. Each module links here the first time it uses one of these terms.

Access token
A credential a client presents to a resource server for access the resource owner granted. In OAuth it carries authorization, not identity, and it is usually a bearer credential.
Account lockout
Refusing every sign-in attempt on an account for a period after too many failed ones. It limits guessing, and it lets anyone who knows a username keep its owner out, so the lock should be temporary and the password reset should stay open.
Act claim
The act claim in a token, naming the party that has been delegated authority. The outermost one is the current actor and nested ones are prior actors, and a consumer applying access control policy must consider only the top-level claims and the current actor. RFC 8693 section 4.1.
Agent card
A JSON document an A2A server publishes, at the standard path /.well-known/agent-card.json in A2A v1.0.1, declaring its name, interfaces, skills and security schemes. It may be signed, and a signature establishes that the key holder wrote it, not who the key holder is.
Algorithm confusion
An attack that changes which algorithm a verifier uses, so a value the attacker knows becomes the verifying key. The classic case swaps RS256 for HS256 and signs with the issuer's public key.
Allowlist
A list of the values a check accepts, with everything else refused. It states what an endpoint is for, so a field, host or algorithm added later stays out until someone lists it. A denylist only describes what existed on the day it was written.
API gateway
A component every request is meant to pass through, applying checks that need only the request. It is a control while it is the only path to the service, which is a property of the network rather than of the gateway.
API key
A credential issued to an application for API access. In this course, it is a secret bearer value checked against a server-side record.
Asymmetric signature
A signature made with a private key and checked with the matching public key. Knowing the public key lets you verify, not sign, so the verifier can't forge signatures.
At-least-once delivery
Delivery in which a sender that receives no acknowledgement sends the event again, so a receiver can get the same event more than once. A repeat is the sender doing its job, not an attack, and the receiver has to handle it without doing the work twice.
Audience
Who a token is for. In a JWT it is the aud claim, which "identifies the recipients that the JWT is intended for". A service checks that its own identifier appears there: when the claim is present and does not name the service processing it, the JWT must be rejected. RFC 7519 section 4.1.3.
Authentication
Checking a claimed identity using evidence such as a credential. Possession of a stolen credential can pass that check.
Authorization
Deciding whether an identity may perform an action on a resource.
Authorization code
A short-lived, single-use value returned through the browser that a client exchanges for a token on a server-to-server request. It is not a credential for the API itself.
Authorization server
The server that authenticates clients, obtains the resource owner's consent, and issues tokens. It owns the authorization and token endpoints.
Back channel
A direct server-to-server request that does not pass through the user's browser. Values sent here are not exposed to browser history or to anything on the redirect path.
Bearer credential
A credential that grants access to whoever presents it, like an API key or most access tokens. If it's stolen, the thief can use it.
Blanket approval
One approval covering a whole session or class of actions. Its worth is the number of an operation's fields it constrains, which is often zero, and then it records that somebody was present rather than controlling what happened.
Blast radius
How much one failure, one compromised agent or one stolen credential can reach. Quotas, narrow scope and one credential per agent make it smaller. None of them prevents the failure.
Blocklist
A list of values a check refuses. For passwords, NIST SP 800-63B-4 section 3.1.1.2 describes "a blocklist that contains known commonly used, expected, or compromised passwords". The whole candidate password is compared with it when a password is set.
Bound approval
An approval carrying a signature over the parameters as the approver saw them, so the executor can confirm it is running the same thing rather than the same identifier. Approving an identifier approves whatever that identifier holds later.
Canonical string
An agreed, exact text description of a request that both sides build the same way before signing. Any difference in bytes produces a different signature.
Canonicalization
Reducing a document to one agreed byte representation before signing, so that reserialising it does not break the signature. For JSON, RFC 8785 sorts object properties recursively and compares names as UTF-16 code units.
Cascading failure
OWASP ASI08: a single fault that "propagates across autonomous agents, compounding into system-wide harm". The entry is about the spread, not about the first fault.
Certificate binding
Tying an access token to the client certificate used on the TLS connection, so the token only works from a connection presenting that certificate. RFC 8705.
Circuit breaker
A component between two stages that stops passing work after a set number of consecutive failures and stays open until it is reset. It pauses a source that keeps failing, including its next output that happens to pass validation.
Claim
A name and value inside a token payload, such as iss, aud or exp. In plain JWT every registered claim is optional, so which ones must be present is decided by the profile you verify against.
Client credentials grant
The OAuth grant a service uses to obtain a token for itself, with no user involved. The client authenticates and receives a scoped token.
Client ID Metadata Document
A client identifier that is itself an HTTPS URL, which the authorization server fetches to read the client's metadata. Preferred over dynamic client registration in MCP revision 2026-07-28. It proves control of a domain, not control of whichever local process is listening on a localhost redirect URI.
Code challenge
The value a client sends in the authorization request to commit to a verifier it has not yet revealed. With the S256 method it is the base64url-encoded SHA-256 hash of the verifier.
Code verifier
A high-entropy random string the client keeps to itself and presents only on the back channel, proving it started the flow. RFC 7636 requires 43 to 128 unreserved characters.
Confidential client
A client that can keep a secret, such as a server-side application. It authenticates to the authorization server in its own right.
Configuration drift
The gap that opens between an environment's settings and the baseline it was built from, usually through changes made by hand and never undone. Nothing reports it unless something compares the two.
Confirmation claim
The cnf claim in a token, naming a key its holder must be able to use. It turns a bearer token into one that also requires proof of possession.
Confused deputy
A service that uses its own authority to carry out a request made on someone else's behalf. The downstream service sees the service's identity and not the user's, so an object check has nothing to compare the request against.
Constant-time comparison
A comparison that takes the same time whether values differ at the first byte or the last. Ordinary string comparison stops at the first difference, which can leak information through timing.
Content-Digest
A header carrying a hash of the message body, defined by RFC 9530. RFC 9421 does not cover message content on its own, so a request body enters an HTTP message signature through a digest field such as this one, and then only if it is a covered component and the receiver recomputes it.
Correlation ID
An identifier an application gives one request, writes into every event that request causes, and returns in an error response. The client can quote it and the operator can find the events and the detail, so the detail never has to be in the response.
CORS
Cross-origin resource sharing. The set of HTTP headers by which a server tells a browser that a response may be handed to a page from a different origin. The browser enforces it and the server only declares; a client that is not a browser is unaffected by it.
Covered components
The ordered list of message parts a signature is computed over. Anything not in the list is outside the signature and can be changed without invalidating it.
Credential stuffing
Replaying username and password pairs taken from another site's breach, on the bet that people reuse passwords. A reused password is right on the first try, so limits on failed attempts slow the attack without stopping it.
Cryptoperiod
"The time span during which a specific key is authorized for use or in which the keys for a given system or application may remain in effect" (NIST SP 800-57 Part 1 Rev. 5). The specifications give you the concept; the length is your judgment to make and defend.
CSRF
Cross-site request forgery. A page on one site makes a logged-in user's browser send a request to another site. The browser attaches that site's cookies by itself, so the request arrives authenticated although the user never asked for it. The attacker does not need to read the response.
Data minimisation
Putting only the fields a task needs into a prompt, chosen from an allowlist. It removes copies rather than filtering them, so it acts on every sink at once: logs, traces, caches, the provider and the answer.
Delegation
An arrangement where one party acts for another while keeping its own identity, so a token names both. RFC 8693 section 1.1 contrasts it with impersonation.
Deny by default
Refusing anything that no rule explicitly allows. Forgetting a new route, role or field then produces a refusal, not an exposure. It protects what nobody thought about, not a rule somebody wrote wrongly.
Deprecation header
The Deprecation HTTP response header field, "used to signal to consumers of a resource (identified by a URI) that the resource will be or has been deprecated". Its value is a date, which may be in the future or in the past. RFC 9745 says to treat it as a hint, and that deprecating a resource does not change how it behaves.
Derived component
A signature input derived from the control data or other parts of the message rather than from a header field, written with a leading @, such as @method, @authority or @path. RFC 9421 section 2.2.
Detection rule
A condition evaluated over logged events that raises an alert when it is met, such as five authorization failures for one account inside a minute. It sees only what the events record.
Double-submit cookie
A CSRF defence that keeps no token on the server. The token arrives in a cookie the page can read, and the page must send it back in a header or a form field. The OWASP CSRF Prevention Cheat Sheet recommends the signed form, an HMAC bound to the session, because a plain value can be planted by anyone who can set a cookie for the domain.
DPoP
Demonstrating Proof of Possession. The client signs a small JWT per request with a key it holds, and the access token names that key, so a stolen token alone is not enough. RFC 9449.
Egress allowlist
The list of hosts a sandbox may send requests to, with every other destination refused. The host is parsed out of the URL and compared exactly, because a substring test passes a lookalike.
Enumeration
Walking a range of identifiers to discover which ones exist. Sequential identifiers make it a loop; a refusal that distinguishes "forbidden" from "not found" makes it a map.
Excessive agency
OWASP LLM03:2026: "the vulnerability that enables damaging actions to be performed in response to unexpected, ambiguous or manipulated outputs from an LLM, regardless of what is causing the LLM to malfunction". OWASP says the root cause is typically one or more of excessive functionality, excessive permissions and excessive autonomy.
Fail closed
Refusing the request when a check cannot complete. The opposite, failing open, lets the request through because the check raised an error, which OWASP Top 10:2025 A10 lists as CWE-636, Not Failing Securely.
False positive
An alert raised for activity that was not an attack. Enough of them and people stop reading alerts, so a threshold is tuned against real traffic and not set once.
Fetch
The browser API that issues HTTP requests from a page, and the name of the WHATWG standard that defines request and response handling, including CORS. A fetch states whether credentials are omitted, included, or sent only to the same origin.
Front channel
A request or response that travels through the user's browser, usually as a redirect. Anything in a front-channel URL may reach browser history, referrer headers, proxy logs, and other apps on the device.
Hardening
Changing a system's settings from the defaults it shipped with to a locked-down baseline: unused features off, default accounts removed, old protocol versions disabled. OWASP API8:2023 asks for it to be a repeatable process.
Hash
A fixed-length fingerprint of data, such as SHA-256. Anyone can compute it, and changing one byte of input changes the output completely. A hash alone proves nothing about who made it.
Hash chain
A list of hashes in which each one covers a record and the hash before it, so changing or removing a record changes every later hash. It shows tampering only to someone who holds a copy of the last hash that the person tampering could not rewrite.
Hidden context
The system instructions and operational context an application places in a model's context and does not show the user. OWASP LLM08:2026 Hidden Context Exposure says it "typically includes the system prompt", and that it should not be "solely relied upon as a security boundary".
HMAC
Hash-based message authentication code. A hash computed with a secret key mixed in, so only key holders can produce or check it.
HSTS
HTTP Strict Transport Security, RFC 6797. A response header that tells a user agent to use only HTTPS for a host for a stated time. It works only in clients that implement it, and only for a host the client already knows, usually because it received the header once over HTTPS.
ID token
A JWT from OpenID Connect that tells a client who signed in. It is for the client, not for an API, and a verifier expecting an access token must reject it.
Idempotency key
A value, such as a transaction ID, that lets the receiver recognize a repeated business operation and return the original result instead of doing the work twice.
Idempotent
A request method is idempotent "if the intended effect on the server of multiple identical requests with that method is the same as the effect for a single such request". RFC 9110 section 9.2.2 names PUT, DELETE and the safe methods, and POST is not among them. An operation sent by POST has to get the property from the application, for example with an idempotency key.
Impersonation
An arrangement where the acting party is given the rights of another and is "indistinguishable from" it in that context, so nothing downstream can tell a different party made the call. RFC 8693 section 1.1.
Improper output handling
Passing a model's output downstream without validating or encoding it for where it is going. OWASP LLM10:2026. The bug is in the calling code rather than in the model's answer.
Incident
One or more adverse events that someone has analysed and declared to be a real compromise or violation. NIST SP 800-61r3 keeps the two apart: it says additional analysis is often needed to decide whether adverse events mean an incident has occurred.
Indirect prompt injection
Injection that arrives in content the model retrieves, such as a web page or a document, rather than from the person typing. Nobody has to attack the system; a document is edited and the agent reads it.
Instance metadata service
A service a cloud platform offers to the machines it runs, conventionally on the link-local address 169.254.169.254. It is reachable from inside and hands out credentials, which makes it a usual target of SSRF.
Insufficient coverage
A signature or approval that protects some of a message and not the rest, so the uncovered parts can change without invalidating it. RFC 9421 section 7.2.1 names it for HTTP signatures; the same reasoning decides which fields an approval must cover.
Introspection
Asking the authorization server whether a token is active right now. It answers for the moment you ask, so caching the answer trades liveness for load.
Issuer
The party that issued a token. In a JWT the iss claim "identifies the principal that issued the JWT" (RFC 7519 section 4.1.1). A verifier compares it with the issuer it expects and confirms that the verifying key belongs to that issuer.
JWKS
JSON Web Key Set. The set of public keys an issuer publishes so verifiers can check its signatures, each identified by a key id. Covered in module 6.
JWS
JSON Web Signature. A format that "represents content secured with digital signatures or Message Authentication Codes (MACs)" (RFC 7515 section 1). It protects integrity and does not hide the content. The JWTs in this course are JWSs whose payload is the claims.
JWT
JSON Web Token. A base64url-encoded header, payload and signature, separated by dots. The header and payload are readable by anyone holding the token; the signature only shows they were not altered.
Key rotation
Replacing a key on a schedule or after exposure. Usually both old and new keys are accepted during a short overlap, then the old one is retired.
keyId
An identifier sent with a signed request telling the receiver which key to verify with. It must never be the key itself.
Kill switch
A control that disables an agent at once: no further calls are dispatched for it and its credential is revoked. Without the revocation it only stops the calls that pass through the orchestrator.
Log injection
Writing a value an attacker controls into a log so that a reader takes it for something else, such as a line break that starts a forged second entry. OWASP Top 10:2025 A09 lists CWE-117, Improper Output Neutralization for Logs, among its mapped weaknesses.
Luhn check
The check digit algorithm card numbers satisfy. In a redactor it separates a card number from any other long number, which stops the redactor blanking order and invoice numbers that people need to read.
Mass assignment
Binding the keys of a client's request straight onto an internal object, so a caller can set a property they should not by adding it to otherwise valid JSON. It was API6:2019 and is now part of OWASP API3:2023 Broken Object Property Level Authorization.
may_act claim
A claim in a token naming the party authorized to become the actor and act on behalf of its subject. It lets the authorization server decide whether a requested delegation was permitted when the subject token was issued, rather than at the moment an actor asks. RFC 8693 section 4.4.
MCP
Model Context Protocol. A JSON-RPC protocol for exposing data and tools to LLM applications. Revisions are dated strings such as 2026-07-28, incremented when a backwards incompatible change lands, and a protected MCP server is an OAuth 2.1 resource server.
mTLS
Mutual TLS. Both client and server present certificates, so each proves its identity to the other when the connection opens.
Multi-factor authentication
Signing in with evidence of at least two different kinds: something you know, something you have, something you are. A password and a PIN are the same kind twice, so they do not count.
no-store
A Cache-Control directive. RFC 9111 section 5.2.2.5 says a cache must not store any part of the request or the response. The same section says it is not a reliable or sufficient mechanism for ensuring privacy.
Non-repudiation
The property that a signer cannot plausibly deny having signed. An asymmetric signature gives a technical version of this, because the verifier could not have produced it, and it holds only as far as private key custody holds.
Nonce
A value used once. The receiver remembers nonces it has seen for a limited time and rejects repeats.
Object-level authorization
Comparing the authenticated caller with the owner recorded on the specific object a request names, after loading it. Its absence is OWASP API1:2023, Broken Object Level Authorization, or BOLA.
One-time password
A short code that is accepted for one sign-in, computed from a secret shared with the server and either a counter (HOTP, RFC 4226) or the time (TOTP, RFC 6238). It shows the caller holds the device with the secret. It can still be phished.
Origin
The scheme, host and port of a URL taken together, serialised with no path and no trailing slash, for example https://app.example. Two URLs are same-origin only when all three agree, so the same host over http is a different origin.
Password spraying
Trying one common password against many accounts, then the next password, so that no single account collects enough failures to lock.
PKCE
Proof Key for Code Exchange. The client commits to a secret verifier by sending its hash, then proves possession of the verifier when redeeming the code, so a stolen code on its own is useless.
Post-filtering
Ranking a whole corpus and then removing results the caller may not see. It returns fewer results than asked for, which discloses that something was removed, and lets other tenants' documents outrank the caller's own. Pre-filtering the corpus avoids both.
Preflight
An OPTIONS request a browser sends before a cross-origin request that is not safelisted, carrying Access-Control-Request-Method and sometimes Access-Control-Request-Headers. It asks whether the CORS protocol is understood, not whether the caller is authorised.
Problem details
The JSON error format RFC 9457 defines, with the media type application/problem+json and the members type, status, title, detail and instance. It is a format, not a rule about what an error may reveal.
Prompt injection
Content that alters a model's behaviour because instructions and data occupy the same sequence with nothing marking which is which. OWASP LLM01:2026 says "no reliable prevention mechanism exists today", so the controls that hold sit either side of the model.
Proof of possession
Showing that you can use a particular key, usually by signing something with it, rather than only presenting a token. It proves the presenter holds the key, not who the presenter is, so an attacker who has the key passes too.
Protected resource metadata
A document a resource server publishes at a well-known location, naming its authorization servers and its supported scopes. RFC 9728. MCP revision 2026-07-28 requires servers to implement it and clients to use it to find the authorization server.
Provenance
The record of where a document or a claim came from, attached to it. Without it an untrusted retrieved claim becomes an unattributed fact, and deleting the source document does not reach what was written from it.
Public client
A client that cannot keep a secret, such as a mobile app or code running in a browser. It relies on PKCE rather than a client secret.
Push notification configuration
In A2A v1.0.1, the webhook a client gives a server for task updates: an HTTPS URL, an optional token unique to the task or session, and optional authentication details. The URL is supplied by the client, so the server should not POST to it blindly.
Quarantine
Stopping a suspect agent from acting while keeping it and its records for review. Whatever dispatches the agent's calls enforces it, so it does not withdraw a credential the agent already holds.
Query string
The part of a URL after the question mark and before any fragment. It often contains named parameters and may be recorded in request logs.
Rate limit
A cap on how many requests, or how much cost, a caller may send in a period of time. The HTTP status code for the refusal is 429, which "indicates that the user has sent too many requests in a given amount of time" (RFC 6585 section 4). It constrains a rate and says nothing about a total, which is what a quota is for.
Redirect URI
The address the authorization server returns the user to with the authorization code. It must be registered in advance and matched exactly, or an attacker can choose where the code goes.
Refresh token
A credential a client uses to obtain a new access token from the authorization server when the current one expires. It is sent only to the authorization server and never to a resource server (RFC 6749 section 1.5), and it is one more long-lived credential to protect.
Replay attack
Resending a captured, valid request unchanged. The signature is still correct, so only freshness and nonce checks stop it.
Reset token
The secret a service sends to an address it already holds so the owner can set a new password. It works as a temporary password, so it has to be random, tied to one account, short-lived and usable once.
Resource indicator
The resource request parameter, which names the service a token is being requested for so the authorization server can bind the token's audience to it. RFC 8707.
Resource server
The server hosting the protected API. It validates the access token, including that the token was issued for it and that the scope covers the operation.
Retrieval-augmented generation
Answering with documents fetched from an index at request time. It makes the document store part of the authorization surface: who may read a document, and who may put one in.
Revocation
Withdrawing a credential, or the grant behind a token, before it expires. A self-contained token does not change when this happens, so a resource server only notices if it consults current state.
Rogue agent
OWASP ASI10: an agent that has come to "deviate from their intended function or authorized scope". The entry is about the behaviour once the drift begins, not about how it began.
Safe method
A request method whose defined semantics are essentially read-only. RFC 9110 section 9.2.1 names GET, HEAD, OPTIONS and TRACE. A browser sends GET for a link or an image tag, so a safe method that changes state can be triggered from another site.
Salt
A random value, different for every stored password, that is hashed together with the password and kept beside the result. Two users with the same password then have different stored hashes, and a table of precomputed hashes is useless.
SameSite
A cookie attribute that tells the browser when to attach the cookie to a request another site caused. Strict never does, Lax does only for a top-level navigation that uses a safe method, and None always does. It is defined in the rfc6265bis Internet-Draft, not in RFC 6265.
Sandbox
A restricted environment for running code or commands, enforced from outside the thing it restricts: which files it can read and write, which hosts it can reach, and what is in its environment. It limits what a wrong step can do, not whether the step is wrong.
Schema
A machine-readable description of the shape a request or response body must have: its fields, their types and their limits. A validator checks a parsed object against it, so a schema cannot refuse what goes wrong before or during parsing.
Scope
The set of permissions a client requests and the resource owner grants. A scope limits what a token can do; it does not decide who may act on a specific object.
Secrets manager
A service that stores secrets such as API keys and signing keys, and from which an application retrieves them when it runs. The secret then has one controlled home and stays out of source code and configuration files.
Sender-constrained token
A token that only works for a holder who can prove possession of a particular key, through a client certificate or a per-request proof.
Session fixation
An attack in which the attacker gets a session identifier they already know into the victim's browser, waits for the victim to log in with it, and then uses the same identifier. Issuing a new identifier at login stops it.
Session identifier
A random value a server stores in a cookie to find the state it keeps for one browser. It has no meaning by itself. After login, whoever presents it is treated as that user, so it is a bearer credential.
Shared secret
A key known to both parties. Either party can create a valid signature, which is why a shared secret can't prove which one did.
Signature
A value computed from data and a key that lets a receiver check the data wasn't changed and came from a key holder.
Signature base
The exact ASCII string an HTTP message signature is computed over: one line per covered component, with the signature parameters as the last line. RFC 9421 section 2.5.
Site
A scheme and a registrable domain, such as https and exampleair.example. Two hosts under the same registrable domain are same-site although they are different origins, so a SameSite cookie is sent with a request from a sibling subdomain.
SPIFFE ID
A URI naming a workload, of the form spiffe://trust-domain/path, carried in a certificate's Subject Alternative Name. It is an identity, not an authorization, and the trust domain has no central registry.
SSRF
Server-side request forgery. Getting a server to make a request to an address the attacker chose, which reaches what only the server can reach. OWASP API7:2023: "Server-Side Request Forgery (SSRF) flaws occur when an API is fetching a remote resource without validating the user-supplied URL."
State handle
A value a stateless server mints to carry state across requests, handed back to it as an ordinary argument. Possession of one is not authentication, so the server binds it to the caller it was minted for and refuses it from anyone else.
Structured logging
Writing each event as named fields in a format a program can parse, such as one JSON object per line, in place of a sentence. The encoder escapes line breaks and quotes inside values, so a value cannot end its own entry.
Sunset header
The Sunset HTTP response header field, which "indicates that a URI is likely to become unresponsive at a specified point in the future" (RFC 8594). When a response carries both, its timestamp must not be earlier than the one in the Deprecation header (RFC 9745 section 4).
Synchronizer token
A random value the server keeps in the user's session and gives to its own pages, which must send it back with every state-changing request. A page on another origin cannot read it, so a forged request arrives without it.
System prompt
The instructions an application puts in front of a model. It travels in the request payload like any other field. OWASP LLM08:2026 counts it as hidden context, whose contents "should not be considered a secret" and which should not be "solely relied upon as a security boundary", and says credentials should not be embedded in it.
Thumbprint
A hash of a key or a certificate, used to identify it. RFC 7638 defines the JWK thumbprint: a hash over only the required members of the key, ordered by name, with no whitespace, so everyone computes the same value. In DPoP it is the jkt value that names the key a token is bound to.
TLS
Transport Layer Security. Encrypts a connection and proves the server's identity to the client. It protects data in transit, not after it arrives.
Token bucket
A rate limiting algorithm: a bucket of some capacity that refills at some rate, where a request spends tokens and is refused when too few are left. Capacity is the burst you are prepared to serve and rate is the average you are prepared to sustain. Its worst moment is a full bucket, which permits the whole capacity at once.
Token exchange
The OAuth grant urn:ietf:params:oauth:grant-type:token-exchange, which trades one security token for another. RFC 8693 requires three request parameters and leaves audience, resource, scope and the issued lifetime to the deployment.
Token passthrough
A server accepting a token that was not issued for it and forwarding it unchanged to a downstream API. Both halves are forbidden by the MCP specification, revision 2026-07-28: the audience check is the first, and the forwarding is what can turn it into a confused deputy.
Token profile
The rules an application declares before verifying any token: allowed algorithms, token type, expected issuer and audience, required claims, key source and clock leeway. Nothing in it is read from the token.
Trust boundary
Any point where a request or a value moves from somewhere you do not control to somewhere you do. Checks belong on the boundary, and a check is only a control if every path to the handler crosses it.
Webhook
An HTTP request a sender posts to a URL the receiver gave it, to report that something happened. Anyone who knows the URL can post to it, so the receiver has to check who sent the event, that it is fresh, and that it has not been handled already.
Workload identity
An identity issued to a running service by its platform, rather than a secret handed to it at deployment. It removes the long-lived value that had to be rotated and distributed; it does not remove ownership, scope or retirement.
Zero trust
A security model in which network location alone earns no trust. NIST SP 800-207 section 2.1 lists it as a tenet: "All communication is secured regardless of network location", and "Network location alone does not imply trust".
