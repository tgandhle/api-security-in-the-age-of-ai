# Contributing

Thank you for reading closely enough to want to fix something.

## Reporting a problem

Open an issue for anything in the course that is wrong, out of date or unclear: a statement a cited source does not support, a broken link, a lab whose output no longer matches its page, an accessibility problem. Say which page, what it says, and what you think it should say, with the source if there is one.

For a security vulnerability, do not open an issue. Follow [SECURITY.md](SECURITY.md).

## Pull requests

Pull requests from outside contributors are not accepted at present. The course is openly licensed (MIT for code, CC BY 4.0 for content: see [LICENSE-CONTENT.md](LICENSE-CONTENT.md)), so you may fork and adapt it, but changes to this repository are made by the maintainer. Open an issue instead, and the maintainer will make the change and credit you in the commit if you wish.

## Reviewing the course

The project wants independent technical review of its lessons ([QUALITY.md](QUALITY.md), criterion 2). If you work in API security, identity or AI security and would review one or more modules, open an issue titled "Review offer" with the modules and your relevant experience. A review is recorded with your name, role, the modules covered, what you found and what changed, so only offer if you are content for that to be published.

## How changes are made

For anyone maintaining the repository, the rules are in [AGENTS.md](AGENTS.md) and [CONVENTIONS.md](CONVENTIONS.md). Every change reaches `main` through a pull request whose checks pass, as signed commits.
