# v1.1.0

The second tagged release of API Security in the Age of AI. It adds the checklist applicability filter, publishes the checklist as data, adds three checklist items, and corrects lessons after a claim-by-claim audit of the AI modules against their sources.

## What is in it

- 38 lessons, modules 0 to 37, unchanged in number and order.
- 38 labs, one per lesson. Python 3 with the standard library, except the five labs that need `cryptography` (modules 3, 5, 6, 7 and 36).
- A review checklist of 328 items: 68 Critical, 168 High, 92 Medium. 117 apply to every API and 211 apply when a fact about the API is true.
- A glossary of 203 terms.

## What changed since v1.0.0

The checklist:

- The hosted checklist has an applicability filter. A reader answers questions about their API and sees the items that apply. The rules are in `CONVENTIONS.md`, and the data and its check are in the repository. Applicability model version 2 removes the rule that an API using OpenID Connect also uses JWTs.
- The checklist is published as JSON and CSV under CC BY 4.0. Item ids are stable, and a retired id is never reused.
- Three items are new, all High, from module 22: inj-11, inj-12 and inj-13. Rendered model output cannot load images from unlisted hosts (inj-11). Approved tool definitions are pinned, and a changed one is refused until reviewed again (inj-12). Tools from several servers are registered under an identifier the client assigns (inj-13).

The lessons:

- Module 22, Prompt injection and output handling, has three new lab parts (checks 54 to 87): per-argument validation of tool calls, image exfiltration through rendered Markdown with a renderer allowlist and a Content Security Policy, and tool definitions, name collisions and pinning.
- Module 20, MCP server authorization: the lab's token for the upstream API now names the user in `sub` and the MCP server in `act`, and the upstream API reads the caller from `act`.
- The AI modules (19 to 25, 31 and 32) were audited claim by claim against their cited sources and their lab output. Corrections were made in modules 19, 20, 21, 23, 24, 25 and 31. In module 25, the lab check that demonstrated the origin control ranked across all tenants; it now applies the tenant filter first, and one exercise has a new correct answer.
- The MCP and A2A lessons were reviewed again on 10 October 2026.
- Long strings in lesson text wrap, so pages reflow at 320 pixels.

The project:

- `QUALITY.md` defines what this project means by enterprise-grade and records the status of each criterion.
- `SECURITY.md`, `CONTRIBUTING.md` and `CODEOWNERS`. Changes reach `main` through pull requests, and the checks run on every pull request.
- Lesson review dates are enforced: a warning on publish, a failure in the release gate, and a daily check.
- `review/` holds the independent review process and five review packets that split the lessons by expertise.
- `accessibility/` holds the manual accessibility test script and the record of one manual pass. The pass found that the skip link left focus on the page body, and that was fixed.
- The published site offers Google Analytics 4, loaded only after the reader chooses Allow analytics in the footer, and never on downloaded pages or local previews. Advertising features are off, and the page address is recorded without its fragment or query string, apart from three campaign labels. `README.md`, Website analytics, says what Google receives.
- A workflow runs the browser checks in Firefox and WebKit, started by hand. It is not part of the release gate.

## Standards and specifications

The list in the v1.0.0 release notes still applies, with these changes:

- Added: Content Security Policy Level 3, W3C Working Draft, 16 September 2026, cited in module 22.
- `AGENTS.md` now records the SHA-256 of the OWASP Top 10 for Agentic Applications PDF that the lessons were checked against, as it already did for the LLM Top 10 PDF.
- The OWASP Agent Control Standard is still cited at version 0.1.3, commit 770f1e0. Version 0.1.4 was released on 15 October 2026. Every passage module 31 quotes is unchanged in it, and moving the pin waits for the next review of that lesson.

The set of RFCs the lessons cite is unchanged.

## Review dates

Every lesson carries the date it was last reviewed. In this release those dates run from 2 October 2026 to 10 October 2026. Every review so far is the author's.

## What the labs and the site run on

- Labs: Python 3. `cryptography` 50.0.1 for the five labs that need it.
- Running a lab in the browser: Pyodide 314.0.7, loaded only when a reader asks for it.
- Author tools: Playwright 1.56.0 and axe-core 4.13.0.

The evidence file attached to this release records the exact Python and browser versions the checks ran on.

## What the attached evidence is, and is not

The release workflow runs every repository check with nothing allowed to skip, compares every published lab transcript with a live run, runs each lab in a browser, and runs automated accessibility checks on every page in light and dark mode at two widths. The record of that run is attached to this release.

It describes one run on one system. It is not a certification. The release gate uses Chromium. The Firefox and WebKit run for this commit is recorded in `QUALITY.md`, criterion 9. Automated accessibility rules are a floor and not a conformance claim.

## Known limits

- No lesson has been reviewed by anyone other than the author. `QUALITY.md`, criterion 2, is Not met, so this release does not claim to meet the project's enterprise-quality criteria.
- OWASP LLM07:2026, Misinformation, is not covered. The coverage page says so and lists what else is left out.
- The course teaches design review from documents and small labs. It does not replace testing a running system.
- The module 37 lab does not implement XML Signature. It uses a stand-in that keeps the one property the wrapping attack depends on, and the lesson says so.
